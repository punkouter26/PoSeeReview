Auth Lifecycle

This report documents the BFF cookie handshake, the Dev/Test FakeAuth bypass, and the API-facing status behavior that keeps browser and API clients on the right side of the redirect boundary.

FakeAuth

Dev/Test only

Maps X-Fake-User and X-Fake-Roles headers to a claims principal, and refuses to exist in Production.

Cookie BFF

Primary session

HttpOnly, SameSite=Strict, Secure cookie named .PoSeeReview.Auth.

OIDC

BFF handshake

  • The WASM client never holds tokens; the cookie is the session.
  • /auth/me reports the server-side auth state back to the client.
  • Client requests stamp X-Session-ID and per-request X-Correlation-ID headers.
  • Anonymous routes are explicit: /auth, /health, /diag, /api/devsession, /api/takedowns, and the SPA fallback.

401 vs 302 enforcement

  • Cookie redirects are converted to 401/403 by the cookie events so API clients do not receive login HTML.
  • /auth/login/microsoft returns a challenge, not a redirect loop, when configured.
  • /api routes rely on the fallback policy, so business slices stay protected even when they do not carry per-endpoint authorize metadata.
